# Live Board — 종합 문서 (Overview & Technical Reference)

> 이 문서 하나로 앱 전체(무엇인지·어떻게 도는지·코드 구조·동기화·배포·한계)를 빠르게 파악할 수 있도록 정리한 종합 레퍼런스.

---

## 1. 한 줄 소개

여러 명이 동시에 **그림(펜)·텍스트·이미지·이미지 비교(Before/After)**를 올리고 편집하는 **웹 기반 실시간 협업 화이트보드.** 무한 캔버스 + 줌/패닝, 실시간 동기화, 늦게 접속해도 현재 화면을 그대로 받음.

---

## 2. 빠른 시작

**로컬 실행**
```bash
npm install
npm start
# http://localhost:4173
```
- 같은 PC: 탭 여러 개로 실시간 동기화 확인 가능.
- 같은 와이파이의 다른 기기: `http://<내 PC 내부 IP>:4173` (cmd `ipconfig`의 IPv4).
- 인터넷 너머의 사람: 로컬만으론 불가 → 배포 필요(§12).

**배포(요약)**: 코드를 GitHub에 올리면 Render가 받아서 실행. 자세한 건 `DEPLOY.md`, 한계는 §13.

## 4. 기능 전체 목록

**도구 (좌측 패널 / 단축키)**
- **이동(V)**: 선택·이동·리사이즈, 다중선택.
- **펜(B)**: 자유 곡선 그리기(색/굵기 지정).
- **텍스트(T)**: 드래그로 박스를 그려 텍스트 입력.
- **지우개(E)**: 선을 실제로 잘라내는 벡터 지우개.

**객체 공통**
- 선택(클릭), 다중선택(드래그 마키 / Shift+클릭), 이동(드래그), 모서리 4점 리사이즈.
- **Alt+드래그 복제**, **Ctrl+C/V 복사·붙여넣기**(다중 포함), **Delete 삭제**.
- **스냅**: 드래그·리사이즈 시 다른 요소의 모서리/중심선에 자동 정렬(분홍 가이드).
- 다중선택 시 **하나의 그룹 박스**로 묶여 일괄 이동·비율 유지 일괄 리사이즈.

**이미지**
- 업로드(파일 선택), **드래그&드롭**, **클립보드 붙여넣기**. base64로 보관.

**텍스트**
- T로 박스 드래그 → 입력. 더블클릭 편집, 바깥 클릭/Esc로 확정(빈 박스는 자동 삭제).
- 사이드 패널에서 **글자 크기·색상** 지정(선택 박스에 즉시 반영).
- 박스 모서리로 폭/높이 조절(텍스트 리플로우, 글자 크기는 유지).

**이미지 비교(Wipe)**
- 이미지 2개 선택 → "이미지 비교 만들기" → 가운데 분할선 박스 생성(원본 유지).
- 분할선 드래그로 A/B 와이프. 선택·이동·리사이즈 가능.

**뷰**
- 무한 캔버스(8000×8000 월드), 휠 패닝 / Ctrl+휠 줌 / Space+드래그 핸드, 줌 배지.
- **실행취소/다시실행**(Ctrl+Z / Shift+Z).

**협업**
- 실시간 동기화 + 늦은 접속자 현재 상태 수신 + 참여자(presence) 표시.

## 5. 아키텍처 개요

```
[브라우저 A]  ──(같은 탭 간: BroadcastChannel)── [브라우저 A의 다른 탭]
     │
     │  업스트림: 프레임당 1회 POST /sync  (메시지 묶음 batch)
     ▼
[ server.js ]  ── 메시지 릴레이 + 최신 스냅샷 보관
     │
     │  다운스트림: SSE /events (지속 연결)로 전 클라이언트에 전파
     ▼
[브라우저 B, C ...]
```

- **클라이언트(app.js)**: 모든 상태(객체·카메라·선택·히스토리)를 보유하고 DOM/SVG로 렌더링.
- **서버(server.js)**: "내용 무관" 중계기 + 최신 보드 스냅샷 1개 보관. 비즈니스 로직 없음 → 객체 타입을 늘려도 서버는 그대로.
- **렌더링 레이어**(`#viewport` 안, 월드 좌표):

| 레이어 | z-index | 내용 |
|---|---|---|
| `drawLayer` (SVG) | 3 | 펜 스트로크(path) |
| `imageLayer` | 2 | 이미지(`.image-item`) |
| `compareLayer` | 2(뒤 DOM) | 비교 박스(`.compare-item`) |
| `textLayer` | 4 | 텍스트(`.text-item`) |
| 오버레이 | 5~8 | 텍스트 드래프트·마키·그룹박스·스냅 가이드 |

## 6. 데이터 모델 (객체 스키마)

```js
// 펜 스트로크 (drawingOps 배열)
{ id, color, size, tool:'pen', points:[{x,y}, ...] }   // SVG path, 곡선 스무딩

// 이미지 (.image-item)
{ id, src:<base64>, x, y, width, z }                   // 높이는 비율로 자동

// 텍스트 (.text-item > .text-body + 핸들 4개)
{ id, x, y, text, color, size, width, minHeight }

// 이미지 비교 (.compare-item > .compare-frame + 핸들)
{ id, type:'compare', x, y, width, height, srcA, srcB, split:0~1, orientation:'v' }
```

**스냅샷(보드 전체 상태)** — 늦은 접속자 동기화·히스토리에 사용:
```js
{ drawingOps:[...], images:[...], texts:[...], compares:[...], fingerprint:'...' }
```
`fingerprint`는 상태 변화 감지용 해시(변화 없으면 히스토리/전송 생략).

좌표는 모두 **월드 좌표**. 화면 표시는 `#viewport`의 `transform: translate(camera.x,y) scale(camera.zoom)`로 변환.

## 7. 실시간 동기화 메커니즘 (핵심)

**2층 구조 = 증분 메시지(실시간) + 스냅샷(정합성)**

1. **업스트림(클라 → 서버)**: 메시지를 큐에 모아 **매 애니메이션 프레임(~16ms)마다 한 번의 POST**로 묶어 전송(`{batch:[...]}`). 그리기 중 수십~수백 건의 POST를 초당 최대 60건으로 축소(Figma식 coalescing).
2. **다운스트림(서버 → 클라)**: **SSE(`/events`)** 지속 연결로 서버가 각 메시지를 전 클라이언트에 즉시 전파. 각 전송은 개별 보호되어, **죽은 연결 하나가 나머지 클라이언트 전파를 막지 않음**(실패한 연결은 즉시 제거).
3. **같은 브라우저 탭 간**: `BroadcastChannel`로도 즉시 동기화.
4. **늦은 접속자**: 서버가 보관한 **최신 스냅샷**을 접속 시 그 클라이언트에게만 1회 전송 → 현재 화면 그대로 수신. (스냅샷은 변경 확정 시 디바운스 400ms로 서버에 저장)
5. **메시지 중복 제거**: 각 메시지 고유 `id`로 dedup(`seenMessageIds`, 최대 4000개), 자기 메시지(source==clientId)는 무시.

**드래그 중 실시간 전송(라이브)** — 이미지·텍스트·비교·그룹의 이동/리사이즈는 드래그 중에도 **throttle(40ms)로 좌표/크기만** 전송해 상대 화면에서 실시간으로 따라 움직인다. **base64 이미지 데이터는 드래그 중 보내지 않고**(좌표만), 마우스를 뗄 때 최종 확정 메시지로 전체를 1회 전송한다.
- 펜/지우개 라이브: `stroke-append` / `erase-segment`.
- 객체 라이브: 좌표·크기만 담은 `image-update`/`text-update`/`compare-update`(src 생략 → 수신측은 기존 이미지 유지).

**유실 대비(중요)** — 증분 메시지는 일부 누락/순서 뒤바뀜이 가능하므로, 동작이 끝날 때 **완성본 전체를 권위있게 재전송**:
- 펜: `stroke-end`에 **선 전체 좌표** 포함 → 중간 점이 빠져도 완성 선으로 재구성.
- 지우개: 뗄 때 **지운 경로 전체(`erase-path`)** 전송 → 누락 구간 재적용.
- 객체: 이동/리사이즈 종료 시 src 포함 전체 페이로드로 최종 확정.

**전송 실패 재시도** — `POST /sync` 실패 시 해당 묶음을 큐 앞쪽에 되돌리고 ~0.8초 후 재전송(상한 4000건). 와이파이 순단·서버 재시작 시 변경 유실을 줄인다.

**메시지 타입 레퍼런스**

| 타입 | 의미 |
|---|---|
| `presence` | 참여자 정보(이름/색/시각) |
| `stroke-start`/`append`/`end` | 펜 시작/점추가(라이브)/완성(전체좌표) |
| `erase-segment`/`erase-path` | 지우개 라이브 구간 / 완성 경로 |
| `clear-drawing` / `reset-all` | 스케치만 지우기 / 보드 전체 초기화 |
| `image-update`/`image-remove`/`image-order` | 이미지 추가·이동·삭제·순서 |
| `text-update`/`text-remove` | 텍스트 갱신·삭제 |
| `compare-update`/`compare-remove` | 비교 박스 갱신·삭제 |
| `board-state` | (서버→신규접속) 전체 스냅샷 |
| `state-store` | (클라→서버) 스냅샷 저장(브로드캐스트 안 함) |

> 충돌 처리: "마지막 동작 우선(last-writer-wins)". CRDT 같은 정교한 병합은 미구현.

## 8. 상호작용 상세 (이동 도구)

- **선택**: 클릭=단일, 빈 영역 드래그=마키 다중선택, **Shift+클릭=토글 추가/제거**.
- **이동**: 선택 요소 드래그. 다중선택 시 그룹 전체 이동.
- **리사이즈**: 모서리 4핸들. 이미지·비교는 **비율 고정**, 텍스트는 가로·세로 독립.
- **그룹 박스**: 2개 이상 선택 시 전체를 감싼 박스 + 핸들 → **비율 유지 일괄 리사이즈**.
- **스냅**: 이동/리사이즈 중 다른 요소의 좌·중·우 / 상·중·하 라인에 근접하면 정렬(임계값은 줌 보정). 분홍 가이드 표시.
- **Alt+드래그**: 복제 후 사본을 드래그(원본 유지).
- **복사/붙여넣기**: Ctrl+C/V, 다중 지원. +24px 오프셋, 사본 자동 선택.

**선택 UI는 줌 무관 고정 크기**: `--zoom` CSS 변수로 외곽선 두께·핸들·가이드선을 역보정 → 확대/축소해도 화면상 크기 일정, 테두리는 요소에 딱 붙음.

## 9. 히스토리 (Undo/Redo)

- 스냅샷 기반. 변경 확정(`pushHistory`) 시 현재 상태 스냅샷을 스택에 push(최대 80개).
- `fingerprint`가 같으면(변화 없음) 기록 생략. Ctrl+Z / Ctrl+Shift+Z(또는 Ctrl+Y).
- `pushHistory`는 동시에 서버 스냅샷 저장(디바운스)도 트리거.
- **실행취소/다시실행도 협업 동기화됨**: `restoreBoardState(broadcastRestore)`가 ① 다른 화면에 `board-state`로 실시간 반영하고 ② 서버 스냅샷(`state-store`)도 갱신 → **새로고침·새 접속자도 실행취소 결과를 그대로** 봄. (히스토리 스택 자체는 클라이언트별 독립)
- **원격 확정 변경도 로컬 히스토리에 기록**: 다른 참여자의 생성/삭제/그리기/이동 확정/undo 결과(`board-state`)를 받은 브라우저도 현재 스냅샷을 히스토리에 push한다. 이 보강으로 한쪽에서 작업한 뒤 다른 쪽에서 Ctrl+Z를 눌렀을 때, 자기 브라우저의 오래된 초기 스냅샷으로 복원되어 화면이 크게 지워지는 문제를 줄였다.
- **드래그 중 임시 업데이트는 히스토리 제외**: 실시간 드래그/리사이즈 메시지는 `transient`로 표시해 상대 화면에는 즉시 반영하되 히스토리에는 쌓지 않는다. 마우스를 놓은 뒤의 확정 업데이트만 undo 단위가 된다.

## 10. 성능 최적화 내역

1. **업스트림 프레임 배칭**: POST 횟수 급감(연결 수 제한 큐잉 해소). → 체감 지연의 주원인 제거.
2. **`keepalive` 제거**: `fetch keepalive`의 64KB 본문 제한 때문에 큰 이미지가 조용히 누락되던 문제 해결.
3. **줌 무관 UI 칩**: 선택 외곽선/핸들/가이드/마키/텍스트드래프트/비교 핸들을 `--zoom` 역보정.
4. **권위적 완성 메시지**(stroke-end 전체좌표, erase-path)로 유실 시 수렴성 강화.
5. **드래그 중 실시간 전송**(throttle 40ms): 객체 이동·리사이즈가 상대 화면에서 즉시 따라 움직임. **드래그 중 base64 미전송**(좌표만)으로 대역폭 폭증 방지.
6. **전송 실패 재시도 큐**(되돌림 + 0.8s 백오프, 상한 4000)로 순단 시 유실 감소.
7. **fingerprint를 stroke 내용 기반**으로 수정 → 지우개로 개수가 그대로여도 변경 감지(늦은 접속자에게 지우기 결과 정확히 반영).
8. **서버 broadcast 견고화**: 죽은/반열린 SSE 연결에 쓰다 예외가 나면 **그 뒤 클라이언트 전파가 통째로 중단**되던 버그 수정(각 전송 try/catch + 죽은 연결 제거). "어떤 창은 받고 어떤 창은 못 받는"·"3명부터 안 되는 듯한" 증상의 원인이었음. ping 루프도 동일 보강.
9. **실행취소/다시실행 서버 동기화**: undo/redo 시 서버 스냅샷도 갱신 → 새로고침·새 접속자에도 반영(이전엔 라이브만 되고 새로고침 시 되돌아갔음).
10. **원격 변경 히스토리 편입**: 원격 확정 변경과 원격 `board-state`를 수신한 클라이언트도 히스토리를 갱신한다. 이전에는 히스토리가 로컬 작업만 알고 있어, 다른 참여자의 작업 후 Ctrl+Z 시 빈 초기 상태로 되돌아가는 듯한 증상이 생길 수 있었다.
11. **라이브 드래그 히스토리 오염 방지**: 드래그 중 좌표 전송은 `transient` 플래그로 구분해 undo 스택에 수십 개의 중간 좌표가 쌓이지 않게 했다.

> 코드로 못 줄이는 지연: **서버까지의 왕복거리(RTT)**. Render 리전이 멀면 그만큼 느림 → 가까운 리전 선택이 추가 개선책.

## 13. 한계 / 알려진 제약

- **메모리 저장**: 보드 상태가 서버 메모리에만 있음 → 서버 재시작/슬립 시 초기화.
- **Render 무료**: 15분 무접속 시 슬립(다음 접속 ~1분 콜드스타트), 월 750 인스턴스-시간.
- **이미지 base64**: 전송/스냅샷 페이로드가 큼. 서버 메시지 상한 30MB(초대형 원본은 막힘).
- **단일 보드**: 방(Room)/파일 개념 없음 — 전원이 하나의 보드 공유.
- **충돌**: 마지막 동작 우선. 동시 같은 객체 편집은 정교히 병합 안 함.
- **유실 극단값**: 완성 메시지까지 통째로 유실되면 새로고침 전까지 어긋날 수 있음.
- **메시지 순서/버전 미보장(미구현)**: 객체별 revision이 없어, 빠른 연속 업데이트가 역전 도착하면 라이브 표시가 잠깐 튈 수 있음(최종 상태는 종료 확정으로 수렴). — 기술검토 문서 §3 참고.
- **스냅샷 stale 덮어쓰기 가능성(미구현 가드)**: 서버가 클라 스냅샷을 revision 검증 없이 저장 → 드물게 늦은 접속자가 약간 과거 상태를 받을 수 있음. — §4 참고.

> 위 두 항목과 방(Room)/DB/WebSocket/CRDT는 `realtime-collaboration-review.md`에서 권고된 다음 단계로, 의도적으로 이번 범위에서 제외(전송계층 재설계 필요).

## 14. 향후 확장 로드맵 (권장 순서)

1. **방(Room) 분리** — URL 방 ID + 서버 상태를 방별로 보관(난이도 中). 서버가 이미 제너릭 중계라 비교적 수월.
2. **영구 저장(DB)** — 재시작 후에도 보존(가장 중요).
3. **파일 목록/관리 UI** — 보드 생성·이름·삭제.
4. **이미지 스토리지 분리** — base64 대신 오브젝트 스토리지로 전송량 절감.
5. **인증/권한** — 누가 어떤 보드에 접근/편집.
6. **WebSocket 전송 + 멀티 인스턴스(Redis pub/sub)** — 더 낮은 지연·대규모 확장.
7. (선택) 비교 기능 고도화: 가로 분할, A/B 교체, 결과 내보내기.
