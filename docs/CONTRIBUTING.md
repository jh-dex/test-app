# 기여 · 작업 지침 (Contributing / Working Guide)

이 문서는 Live Board 저장소에서 작업하는 **모든 사람과 AI 도구(어떤 LLM이든)** 가 따라야 할 기본 지침입니다. 도구에 종속되지 않는 범용 규칙이므로, 작업을 시작하기 전에 먼저 읽어 주세요.

프로젝트 전체 구조·동기화·한계는 `docs/OVERVIEW.md`, 실시간 협업 기술 검토는 `docs/realtime-collaboration-review.md`, 변경 이력은 `docs/CHANGELOG.md`를 참고하세요.

## ⭐ 필수 규칙: 모든 변경은 문서로 남긴다

코드를 바꾸는 **모든 작업(기능 추가 · 동작 변경 · 버그 수정 · 성능 개선 · 제거)** 은 **반드시 `docs/CHANGELOG.md` 맨 위에 항목을 추가**합니다.

- 형식은 `docs/CHANGELOG.md` 상단의 작성 규칙을 따릅니다: `날짜 — 유형: 요약` + **증상/목적 · 원인 · 변경(파일·함수) · 검증 · 영향/사이드이펙트**.
- 사소한 변경이라도 한 줄은 남깁니다. **커밋 메시지로만 끝내지 않습니다.**
- 작업을 마치기 전에 CHANGELOG 갱신 여부를 스스로 확인합니다.

## 작업 원칙

- **실시간 동기화 로직**(`app.js`의 `broadcast` / `handleRealtimeMessage` / `restoreBoardState` / 히스토리·`pushHistory`)을 건드릴 때는 단일 사용자뿐 아니라 **2명 이상 동시 편집** 시나리오로 반드시 검증합니다. (혼자 테스트하면 멀쩡해 보이는 동기화 버그가 많습니다.)
- 변경이 **다른 기능에 주는 사이드이펙트**를 점검하고, CHANGELOG의 "영향" 항목에 명시합니다.
- 가능하면 수정 전/후를 동일한 방법으로 비교 검증합니다. 동기화 변경은 클라이언트 2개를 모사하는 방식(예: jsdom 기반 하니스)으로 desync 여부를 확인하는 것을 권장합니다.
- 서버(`server.js`)는 "내용 무관" 중계기로 유지합니다. 가능하면 객체 타입을 늘려도 서버를 고치지 않아도 되도록 클라이언트에서 처리합니다.
- 이미지는 base64로 전송/보관되어 페이로드가 큽니다. 동기화 코드를 바꿀 때 전송량이 불필요하게 늘지 않는지 확인합니다.

## 빠른 점검

- `npm start` → http://localhost:4173 , 탭 2개 이상으로 실시간 동기화 확인.
- `node --check app.js` , `node --check server.js` 로 문법 확인.
