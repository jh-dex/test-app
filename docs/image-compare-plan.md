# 이미지 비교(Wipe) 기능 기획안

> Live Board에 "두 이미지를 겹쳐 가운데 분할선을 드래그하며 A/B를 비교"하는 기능(Before/After Wipe Slider)을 추가하기 위한 개발 기획안.

---

## 1. 한 줄 요약

캔버스 위 **두 이미지를 하나의 "비교 박스"로 합쳐**, 가운데 분할선을 좌우(또는 상하)로 드래그하면 한쪽엔 A 이미지, 다른 쪽엔 B 이미지가 보이는 **Before/After 비교 객체**를 추가한다. 기존 이미지/텍스트 객체와 동일한 방식으로 **선택·이동·리사이즈·실시간 동기화·undo**가 모두 동작한다.

---

## 2. 목적과 배경

- 디자인 시안 비교, 보정 전/후, 변경 전/후 등 **두 시각물을 같은 프레임에서 겹쳐 비교**하려는 수요가 큼.
- 현재는 이미지를 나란히 놓고 눈으로 비교해야 함 → 정렬·크기 차이로 비교가 부정확.
- 협업 보드 특성상, 한 사람이 분할선을 움직이면 **다른 참여자도 실시간으로 같은 와이프를 보는 것**이 핵심 가치.

---

## 3. 사용자 시나리오 (UX 흐름)

1. 사용자가 캔버스에 이미지 2개를 올린다(기존 기능).
2. 이동 도구(V)로 **이미지 2개를 다중 선택**한다(이미 구현된 드래그 다중선택 활용).
3. 사이드 패널에 나타난 **"이미지 비교 만들기"** 버튼을 누른다.
4. 두 이미지가 사라지고, 그 자리에 **하나의 비교 박스**가 생성된다(왼쪽=A, 오른쪽=B, 분할선 50%).
5. 박스 가운데 **분할선 핸들**을 드래그하면 경계가 이동하며 A/B가 번갈아 드러난다.
6. 비교 박스는 다른 객체처럼 **선택·이동·모서리 리사이즈**가 가능하고, 선택 시 패널에서 **방향 전환(좌우/상하)·A/B 교체·50% 리셋**을 할 수 있다.
7. 이 모든 동작은 **다른 참여자 화면에 실시간 반영**되며, 늦게 접속한 사람도 현재 상태(분할 위치 포함)를 그대로 본다.

---

## 4. 기능 요구사항

### 4.1 필수(MVP)
- 두 이미지를 선택해 비교 박스로 합치기.
- 분할선 드래그로 와이프(0~100%).
- 비교 박스 선택·이동·모서리 리사이즈(기존 인프라 재사용).
- 실시간 동기화(생성/이동/리사이즈/분할 이동/삭제) + 스냅샷(늦은 접속자) + undo/redo.
- 두 이미지는 같은 박스에 **동일 기준으로 맞춰 정렬**(`object-fit: cover`)되어 위치가 어긋나지 않음.

### 4.2 선택(2차)
- 분할 방향 전환(세로 분할 ↔ 가로 분할).
- A/B 교체(swap).
- 분할선 50% 리셋.
- A/B 라벨 표시 토글.

### 4.3 비기능
- 분할선 드래그는 부드럽게(로컬 즉시 반영), 네트워크 전송은 **스로틀**(예: 60~80ms)로 과도한 트래픽 방지 — 기존 펜 스트로크/텍스트 편집과 동일한 패턴.
- 비교 박스는 z-순서(레이어) 정렬 대상에 포함.

## 5. 데이터 모델

새 객체 타입 `compare`를 추가한다(이미지/텍스트와 동급).

```js
{
  id: string,            // crypto.randomUUID()
  type: 'compare',
  x: number, y: number,  // 월드 좌표(좌상단)
  width: number,         // 박스 폭(월드 px); height는 종횡비로 산출
  srcA: string,          // base64 data URL (왼/위 이미지)
  srcB: string,          // base64 data URL (오른/아래 이미지)
  split: number,         // 0~1, 분할선 위치 (기본 0.5)
  orientation: 'v'|'h',  // 'v'=세로 분할(좌우 와이프), 'h'=가로 분할(상하 와이프)
  z: number              // 레이어 순서
}
```

> 이미지를 base64로 보관하는 현재 방식을 그대로 따른다(일관성). 비교 박스는 이미지 2장을 들고 있으므로 페이로드가 큼 → **6장 한계/성능** 항목 참고.

## 6. 렌더링 방식 (DOM/CSS)

표준 Before/After 슬라이더 기법을 사용한다.

```
.compare-item (박스, position:absolute, width=박스폭, overflow:hidden)
├─ img.compare-base   (B 이미지, 박스 전체를 채움 / object-fit:cover)
├─ .compare-clip      (A 이미지를 담는 클리핑 박스, overflow:hidden, width = split*박스폭)
│    └─ img.compare-top (A 이미지, 너비를 "박스 전체 폭"으로 고정 → 잘려도 안 찌그러짐)
├─ .compare-divider   (분할선 + 가운데 원형 핸들, left = split*박스폭)
└─ .resize-handle ×4  (모서리 리사이즈, 기존 이미지와 동일)
```

핵심 포인트:
- **A는 클리핑 박스 안에서 "박스 전체 폭"으로 고정**한다. 클리핑 박스 폭만 `split`에 따라 줄어들므로, A는 찌그러지지 않고 잘려서 보인다(정상적인 와이프).
- 두 이미지 모두 같은 박스 크기에 `object-fit: cover`로 채워 **프레임을 일치**시킨다.
- 가로 분할(`h`)일 땐 width 대신 height 기준으로 동일 로직 적용.

## 7. 상호작용 설계

| 동작 | 트리거 | 처리 |
|---|---|---|
| 생성 | 이미지 2개 선택 → "비교 만들기" | 두 이미지 제거 + compare 객체 생성(첫 이미지 위치/크기 기준) |
| 선택 | 이동 도구로 클릭 | 기존 selection 인프라(`selectedIds`)에 편입 |
| 이동 | 박스 본문 드래그 | 기존 move 로직 재사용(좌표만 갱신) |
| 리사이즈 | 모서리 핸들 드래그 | 기존 이미지 리사이즈와 동일(종횡비 유지) |
| **와이프** | **분할선 핸들 드래그** | `split` 갱신 → 즉시 재렌더 + 스로틀 전송 |
| 방향 전환/스왑/리셋 | 패널 버튼 | `orientation`/`srcA·srcB`/`split` 갱신 |
| 삭제 | Delete | 기존 삭제 로직 재사용 |

분할선 핸들과 리사이즈 핸들, 본문 클릭을 **이벤트 타깃으로 구분**한다(텍스트 박스에서 핸들 vs 본문을 구분한 방식과 동일).

## 8. 실시간 동기화 설계 (기존 패턴 재사용)

이 프로덕트의 동기화는 "증분 메시지(실시간 부드러움) + 스냅샷(정합성/늦은 접속자)" 2층 구조다. 비교 기능도 동일하게 얹는다.

- **새 메시지 타입**
  - `compare-update` : 생성/이동/리사이즈/분할 변경 시 전체 페이로드 전송(이미지 `image-update`와 동형).
  - `compare-remove` : 삭제.
- **분할선 드래그 중**에는 `compare-update`를 **스로틀(60~80ms)**로 전송해 다른 참여자도 와이프를 부드럽게 본다(펜 `stroke-append`, 텍스트 편집 throttle과 동일).
- **스냅샷 포함**: `snapshotBoardState()`에 `compares` 배열을 추가 → 서버가 보관하는 최신 스냅샷에 비교 객체가 포함되어, **늦게 접속한 사람도 분할 위치까지 동일하게** 본다.
- **히스토리**: 생성/삭제/이동/리사이즈/분할 변경의 "확정 시점"에 `pushHistory()` → undo/redo 및 스냅샷 자동 저장에 편입.
- **충돌 처리**: 현재 프로덕트 정책과 동일하게 "마지막 동작 우선(last-writer-wins)". 두 명이 동시에 같은 분할선을 잡는 경우는 MVP 범위 밖.

## 9. 기존 코드 통합 지점 (구체)

| 파일 | 추가/수정 |
|---|---|
| `index.html` | 사이드 패널에 "이미지 비교 만들기" 버튼(2개 선택 시 활성), (2차) 방향/스왑/리셋 컨트롤. 비교용 레이어 컨테이너는 기존 `imageLayer` 재사용 또는 `compareLayer` 신설. |
| `styles.css` | `.compare-item`, `.compare-clip`, `.compare-divider`(선+핸들), 호버/선택 스타일(기존 패턴 일치). |
| `app.js` | ① `placeCompare()/getComparePayload()/serializeCompares()` 추가(이미지 함수들과 동형) ② `snapshotBoardState`/`restoreBoardState`/`makeHistoryFingerprint`에 `compares` 반영 ③ `handleRealtimeMessage`에 `compare-update`/`compare-remove` 처리 ④ `pointerDown/Move/Up`에 분할선 드래그(`wipe`)·이동·리사이즈 분기 ⑤ "비교 만들기" 액션(선택 2개 검증 → 생성, 원본 2개 제거) ⑥ reset/clear 시 compare 레이어 정리. |
| `server.js` | **변경 불필요.** 서버는 메시지를 그대로 중계하고 스냅샷(payload)을 통째로 보관하므로, `compares`가 포함된 스냅샷·새 메시지 타입이 자동으로 전파된다. |

> 통합 난이도가 낮은 이유: 서버가 "내용 무관 중계 + 스냅샷 보관" 구조라, 클라이언트에 객체 타입 하나를 더하는 작업만으로 실시간/늦은접속/undo가 전부 따라온다.

### 구현 방식 선택지
- **(A) 비교 객체를 기존 `.image-item` 인프라에 얹기** — 이동/리사이즈/레이어순서/선택 코드를 거의 그대로 재사용. 단, 리사이즈의 종횡비 계산을 박스 기준으로 보정 필요. → **MVP 권장(빠름).**
- **(B) 독립 `compare` 레이어/모델** — 코드가 더 깔끔하고 제어가 자유로우나 이동/리사이즈/순서 로직을 일부 재작성. → 기능 확장 여지가 클 때.

## 10. UI 디자인 가이드

- **분할선**: 1~2px 흰색 선 + 양옆 옅은 그림자(어떤 이미지 위에서도 보이게). 가운데 **원형 핸들**(좌우 화살표 아이콘). Figma·표준 비교 슬라이더 관례를 따른다.
- **호버/선택**: 다른 객체와 동일하게 호버 시 얇은 파란 외곽선, 선택 시 파란 박스 + 모서리 핸들.
- **패널 컨트롤(2차)**: 방향(좌우/상하) 토글, A/B 교체, 50% 리셋, (선택) A/B 라벨 토글.
- **생성 버튼**: 이미지가 정확히 2개 선택됐을 때만 활성화, 그 외엔 비활성 + 안내 문구.

## 11. 엣지 케이스 / 제약

- **종횡비가 다른 두 이미지**: 같은 박스에 `object-fit: cover`로 맞추므로 일부 잘림은 발생(정렬 우선). 필요 시 정렬 기준(중앙) 노출은 2차.
- **대용량 이미지**: 비교 박스는 base64 2장을 보유 → 스냅샷/전송 페이로드가 큼. 다수일 때 무거워질 수 있음(현재 이미지 한계와 동일선상). 향후 이미지 스토리지 분리로 해소.
- **분할선이 0/1 끝단**: 한쪽만 보이게 정상 동작하도록 clamp(0~1).
- **원본 이미지 보존 여부**: 기본은 "원본 2개를 비교 객체로 흡수(삭제)". 보존 옵션은 결정 필요(아래).
- **동시 편집 충돌**: last-writer-wins(현 정책 동일).
- **undo 범위**: 분할선 미세 드래그마다 히스토리가 쌓이지 않도록, **드래그 종료(pointerup) 시 1회** 히스토리 기록(드래그 중에는 스로틀 전송만).

## 12. 단계별 개발 계획

1. **데이터/렌더링**: `compare` 모델 + `placeCompare()` 렌더링(정적 분할 50%) → 화면에 박스 표시.
2. **생성 플로우**: 이미지 2개 선택 → "비교 만들기" → 원본 흡수 + compare 생성.
3. **와이프 인터랙션**: 분할선 드래그로 `split` 갱신(로컬).
4. **이동/리사이즈 통합**: 기존 선택/이동/리사이즈 인프라에 편입.
5. **동기화/스냅샷/히스토리**: `compare-update`/`compare-remove`, 스냅샷 `compares`, throttle 전송, pushHistory.
6. **검증**: 로컬 다중 접속 시뮬레이션(스냅샷에 compare 포함·분할 위치 전파 확인) + 브라우저 수동 테스트.
7. **(2차) 옵션 UI**: 방향 전환/스왑/리셋/라벨.

---

## 13. 결정 필요 사항 (개발 착수 전)

1. **원본 이미지 처리**: 비교 생성 시 원본 2개를 (a) 흡수해 제거 _[권장]_ vs (b) 그대로 두고 별도 객체 생성.
2. **방향 지원 범위**: MVP에서 세로 분할(좌우 와이프)만 vs 가로 분할까지.
3. **생성 진입점**: "선택 2개 → 패널 버튼" _[권장]_ vs 별도 도구 버튼(T처럼) vs 우클릭 메뉴.
4. **A/B 지정 규칙**: 선택 순서/레이어 순서 중 무엇을 A로 둘지(예: 더 아래 레이어=A).

## 14. 향후 확장

- 분할선 각도(대각선) 와이프, 차이(diff) 하이라이트 모드, 슬라이더 자동 애니메이션, 3장 이상 비교, 비교 결과 이미지로 내보내기.
