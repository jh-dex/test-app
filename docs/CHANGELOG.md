# 변경 이력 (Changelog)

> 이 프로젝트의 모든 기능 추가 · 동작 변경 · 버그 수정 · 성능 개선은 **반드시 이 파일에 기록**합니다.
> (작업 지침은 `docs/CONTRIBUTING.md` 참고)
>
> **작성 규칙**
> - 최신 항목을 맨 위에 추가한다.
> - 각 항목은 `날짜 — 유형: 한 줄 요약` 헤더 + 아래 항목을 채운다: **증상/목적**, **원인**(버그일 때), **변경**(파일·함수), **검증**, **영향/사이드이펙트**.

## 2026-06-15 — Added: 홈 캔버스 미리보기 썸네일

**증상/목적**
홈의 최근 캔버스 목록에서 파일 이름과 최근 시간만으로는 여러 캔버스를 구분하기 어려웠다. 복잡한 파일 관리 기능을 늘리기보다, 각 캔버스의 대략적인 내용을 카드에서 바로 식별할 수 있도록 가벼운 미리보기를 추가했다.

**변경** (`app.js`, `styles.css`)
- 최근 캔버스 `localStorage` 항목에 `preview` 요약 데이터를 함께 저장하도록 변경.
- 보드 스냅샷에서 펜 선, 이미지, 텍스트, 비교 박스의 위치와 개수를 축약해 미리보기 데이터를 생성.
- 홈 카드의 기존 작은 아이콘을 보드형 썸네일 영역으로 교체.
- 로컬 편집, 원격 편집 반영, 서버 snapshot 복원 시 현재 캔버스 미리보기가 갱신되도록 연결.
- 실제 이미지 원본/base64를 저장하지 않고 위치/형태 요약만 저장해 `localStorage` 부담을 줄임.

**검증**
- `node --check app.js`
- `node --check server.js`
- `git diff --check`
- 임시 로컬 서버에서 `/` GET 200 응답 확인.

**영향/사이드이펙트**
- 기존 최근 캔버스 목록은 그대로 읽힌다.
- 기존 캔버스는 열어서 편집하거나 서버 snapshot이 복원된 뒤부터 미리보기가 생긴다.
- 서버 저장소/API 계약은 변경하지 않았다.
- 인앱 브라우저 `iab`가 이 세션에서 제공되지 않아 실제 화면 렌더링 검증은 수행하지 못했다.

## 2026-06-15 — Changed: 홈을 파일 선택 화면으로 분리

**증상/목적**
홈이 편집 화면 위에 뜨는 오버레이라, 여러 캔버스 중 하나를 선택해서 들어가는 “파일 브라우저 → 편집기” 흐름이 분명하지 않았다. 복잡한 파일 관리 기능 없이도 사용자가 홈에서 캔버스를 고르고, 선택한 캔버스에 들어가는 구조로 정리했다.

**변경** (`app.js`, `styles.css`)
- `/`는 캔버스 파일 선택 홈으로 동작하고 편집 도구/보드는 숨기도록 변경.
- `?canvas=...`가 있을 때만 해당 캔버스 편집기로 진입하고 실시간 동기화를 시작하도록 변경.
- 홈의 최근 캔버스 목록을 큼직한 카드형 리스트로 정리.
- 홈에 머무르는 것만으로 `default` 캔버스가 최근 목록에 생기거나 동기화에 접속하지 않도록 변경.
- 편집 화면의 `홈`/현재 캔버스 표시 클릭은 홈(`/`)으로 이동하도록 변경.

**검증**
- `node --check app.js`
- `node --check server.js`
- `git diff --check`
- 임시 포트 서버에서 `/` 홈, `?canvas=...` 편집기 정적 로드와 `/sync?canvas=...` POST 응답 확인.

**영향/사이드이펙트**
- 최근 캔버스 목록은 여전히 브라우저 `localStorage` 기반이다.
- 각 캔버스의 보드 내용은 서버 프로세스가 살아있는 동안 캔버스별 메모리 스냅샷으로 유지된다.
- 서버 재시작 후에도 유지하려면 다음 단계에서 JSON 파일/SQLite/DB 저장소가 필요하다.

## 2026-06-15 — Changed: 캔버스 홈 UX 정리

**증상/목적**
캔버스 분리 1차 구현은 기능적으로는 동작하지만, 사용자가 홈으로 돌아갔을 때 최근 파일을 고르고 새 파일을 만드는 흐름이 파일 브라우저처럼 명확하지 않았다. 홈을 “현재 작업으로 돌아가기 / 최근 캔버스 열기 / 새 파일 만들기”의 기준점으로 정리했다.

**변경** (`index.html`, `app.js`, `styles.css`)
- 현재 캔버스 표시를 클릭 가능한 홈 진입 버튼으로 변경.
- 홈에 `현재 작업으로 돌아가기` 액션과 `최근 캔버스` 섹션 제목을 추가.
- 새 캔버스는 `canvas-...` ID 대신 `새 캔버스 날짜/시간` 형태의 읽기 쉬운 로컬 제목으로 최근 목록에 저장.
- `/`로 돌아왔고 최근 캔버스가 있으면 홈을 자동으로 열어 파일 선택 흐름이 자연스럽게 이어지도록 변경.
- 최근 목록에서 현재 열려 있는 캔버스를 강조하고 액션 문구를 `작업 중`/`열기`로 분리.

**검증**
- `node --check app.js`
- `git diff --check`

**영향/사이드이펙트**
- 캔버스 이름은 아직 브라우저 `localStorage`에만 저장되는 표시용 제목이다.
- 서버 저장 구조와 협업 동기화 API는 변경하지 않았다.

## 2026-06-15 — Added: 캔버스 파일 분리 1차 구조

**증상/목적**
기존 Live Board는 서버와 클라이언트가 모두 단일 보드만 전제로 동작해, 새 캔버스/홈/캔버스 전환 기능을 붙이면 서로 다른 작업 내용이 섞일 수 있었다. 먼저 다른 기능에 영향이 적은 범위에서 URL 기반 캔버스 분리 구조를 추가했다.

**변경** (`server.js`, `index.html`, `app.js`, `styles.css`)
- 서버의 단일 `boardSnapshot`/`clients`를 캔버스 ID별 `Map`으로 분리.
- `/events?canvas=...`, `/sync?canvas=...` 기준으로 SSE 구독자와 최신 보드 스냅샷을 분리.
- 클라이언트가 URL의 `canvas` 파라미터를 읽고, BroadcastChannel 이름도 캔버스별로 분리.
- 상단에 `홈`/`새 파일` 버튼과 현재 캔버스 표시를 추가.
- 홈 오버레이에서 `localStorage` 기반 최근 캔버스를 열 수 있게 추가.

**검증**
- `node --check server.js`
- `node --check app.js`

**영향/사이드이펙트**
- 기존 `/` 접속은 `default` 캔버스로 유지된다.
- 캔버스 목록은 아직 브라우저 `localStorage` 기반이므로 기기/브라우저 간 공유 목록은 없다.
- 보드 데이터는 기존과 동일하게 서버 메모리에 저장되므로, 서버 재시작 후 영구 보존은 아직 지원하지 않는다.

## 2026-06-15 — Fixed: 실시간 협업 중 실행취소(Ctrl+Z)/다시실행 동기화 어긋남

**증상**
다른 참여자와 동시에 작업하는 중 한쪽이 Ctrl+Z(실행취소)를 누르면 그 결과가 상대 화면에 제대로 반영되지 않고, 두 사람이 보는 캔버스가 영구적으로 어긋났다. 혼자서 한 동작씩 천천히 테스트하면 정상으로 보여 원인 파악이 어려웠다(이전 수정들이 반복 실패한 이유).

**원인**
`undo()` / `redo()` → `restoreBoardState()` 가 **실행한 사람의 로컬 전체 스냅샷을 `board-state` 메시지로 통째 브로드캐스트**했다. 이 스냅샷에는 아직 병합되지 않은 **다른 참여자의 동시 편집이 빠져 있어**, 수신측이 전체를 덮어쓰는 순간 상대 작업이 사라지고 양쪽 상태가 수렴하지 못했다. 또한 디바운스된 `state-store`(서버 스냅샷) 경합으로 늦은 접속자가 받는 스냅샷까지 오염됐다.

**변경** (`app.js`)
- **undo/redo가 전체 스냅샷 대신 변경분(diff)만 전송.** 복원 직전 상태와 복원 후 상태를 비교해, 실제로 바뀐 stroke/image/text/compare 객체만 기존 메시지(`stroke-end`, `image-update`/`image-remove`/`image-order`, `text-update`/`text-remove`, `compare-update`/`compare-remove`)로 송신한다. → 상대가 만진 다른 객체는 보존되어 양쪽이 수렴한다. (`broadcastBoardDiff()` 신설, `restoreBoardState()`에서 복원 전 `before` 스냅샷 캡처 후 호출)
- **`stroke-remove` 메시지 타입 신설** + 수신 핸들러. 개별 펜 스트로크 삭제용(기존엔 `clear-drawing` 전체 삭제만 존재).
- **객체별 송신순서 가드** 추가(`objectOpSeq` 맵 + `isStaleObjectOp()`/`noteObjectOp()`, `GUARDED_OBJECT_OPS`). 같은 사용자가 보낸 더 오래된 메시지가 뒤늦게 도착해도 최신 상태를 되살리지 못하게 차단한다(메시지 재정렬 내성). 서로 다른 사용자 간에는 기존의 last-writer-wins 동작을 그대로 유지.
- 클라이언트가 `board-state` 전체를 브로드캐스트하던 코드 제거. (서버 → 늦은 접속자에게 내려주는 `board-state` 스냅샷 경로는 그대로 유지)

**검증**
jsdom으로 클라이언트 2개 + 서버 릴레이(server.js 동작) 를 모사하는 재현 하니스로 34개 시나리오를 동일 코드로 before/after 비교.
- 수정 전: **8개 실패** (동시편집 중 undo, 늦은 접속자 오염 등).
- 수정 후: **34개 전부 통과**.
- 단일 undo/redo, 이미지 undo/redo, 그리기·이미지 이동, 메시지 재정렬, 늦은 접속 동기화 모두 회귀 없음 확인. `node --check app.js` 통과.

**영향 / 사이드이펙트**
- 기능 회귀 없음.
- **성능 개선**: 기존 undo는 base64 이미지를 포함한 보드 전체를 매번 재전송했으나, 이제 바뀐 객체만 전송한다.
- 남은 한계(차기 과제): 서버 스냅샷 저장이 여전히 last-writer-wins라, 극단적인 동시 타이밍에서 늦은 접속자 정합성은 서버 revision 도입으로 추가 보강 필요. → `docs/realtime-collaboration-review.md` §3·§4 참고.
